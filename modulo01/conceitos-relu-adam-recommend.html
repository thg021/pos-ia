ReLU — A "peneira" dos neurônios

ReLU = Rectified Linear Unit

Fórmula

f(x) = max(0, x)

Entrada negativa

−5.2 → 0

bloqueado

Entrada positiva

3.7 → 3.7

passa intacto

Por que usar ReLU?

Sem funções de ativação, uma rede neural seria apenas multiplicação de matrizes — só consegue aprender relações lineares (retas). O mundo real é cheio de relações complexas. ReLU introduz não-linearidade e permite que a rede aprenda combinações, exceções e padrões complexos.

Analogia: Uma peneira que deixa passar apenas sinais positivos (relevantes) e bloqueia os negativos (irrelevantes). Cada neurônio tem sua própria peneira.

ReLU vs Sigmoid

ReLU Sigmoid
Fórmula max(0, x) 1 / (1 + e^-x)
Saída 0 a ∞ 0 a 1
Uso Camadas intermediárias Camada de saída (probabilidade)
Vantagem Rápida, evita gradiente desvanecendo Ideal para probabilidades (0–1)

Adam Optimizer — Como a rede aprende

Adam = Adaptive Moment Estimation

O conceito base: Gradiente Descendente

A rede começa com pesos aleatórios e erra muito. A cada epoch, o algoritmo calcula:

1

O erro atual — medido pela função de loss

2

Qual direção reduz o erro — o gradiente

3

Quanto ajustar cada peso — a taxa de aprendizado

Analogia da montanha: Você está numa montanha com neblina e quer chegar ao vale (erro mínimo). Sente a inclinação do chão e sempre dá um passo para o lado mais íngreme para baixo.

Como Adam resolve o problema dos passos fixos

Passo muito grande

Pula o vale, oscila para sempre sem convergir

Passo muito pequeno

Chega lá, mas demora muito — epochs demais

Adam é adaptativo — ajusta o tamanho do passo automaticamente para cada peso:

m

Momento 1 — média dos gradientes recentes ("para onde tenho ido")

v

Momento 2 — média dos quadrados ("quão incerto estou")

Analogia do motorista: Adam é um motorista experiente. Nas retas, acelera. Nas curvas, freia. E ainda se lembra das curvas anteriores para antecipar.

Evolução do loss durante o treino

Epoch 1 loss = 0.68 — chutes aleatórios
Epoch 10 loss = 0.42 — começa a aprender
Epoch 50 loss = 0.19 — convergindo
Epoch 100 loss = 0.08 — próximo do mínimo

No código

// modelTrainingWorker.js — parte04, linha 261
model.compile({
    optimizer: tf.train.adam(0.01),   // taxa de aprendizado inicial = 0.01
    loss: 'binaryCrossentropy',       // mede o erro em problemas sim/não
    metrics: ['accuracy']
})

binaryCrossentropy = função de perda para problemas binários (comprou / não comprou). Penaliza muito quando o modelo está muito errado com alta confiança.

3

Como a função recommend() funciona

A função estava vazia no código do curso — aqui está a implementação completa com explicação linha a linha.

Lógica em 5 passos

1

Pegar o usuário atual e transformá-lo em vetor numérico com encodeUser()

2

Para cada produto: transformar em vetor, juntar [vetor usuário] + [vetor produto]

3

Perguntar ao modelo: "qual a chance de compra?" → retorna número entre 0 e 1

4

Ordenar por pontuação (maior = mais recomendado) e remover o que já foi comprado

5

Retornar os top 5 via postMessage() para a página principal

Implementação

function recommend({ user }) {
    const context = _globalCtx
    const model   = _model

    // 1. Codifica o usuário em vetor numérico
    const userVector = encodeUser(user, context).dataSync()

    // 2. Pontua cada produto
    const scores = context.products.map(product => {
        const productVector = encodeProduct(product, context).dataSync()

        // junta os vetores (igual ao que foi feito no treino)
        const input = tf.tensor2d([[...userVector, ...productVector]])

        // modelo retorna número entre 0 e 1
        const score = model.predict(input).dataSync()[0]

        return { product, score }
    })

    // 3. Ordena do maior para o menor
    const sorted = scores.sort((a, b) => b.score - a.score)

    // 4. Remove produtos já comprados
    const alreadyBought = new Set(user.purchases.map(p => p.name))
    const recommendations = sorted
        .filter(item => !alreadyBought.has(item.product.name))
        .slice(0, 5)

    // 5. Envia para a página principal
    postMessage({
        type: workerEvents.recommend,
        user,
        recommendations: recommendations.map(r => r.product)
    })
}

Conexão entre os três conceitos

A

Adam Optimizer

Ajusta os pesos da rede a cada epoch com base no gradiente

R

ReLU

Pesos ajustados mudam como cada neurônio reage — ReLU decide quais sinais passam em cada camada

P

recommend() / predict()

Depois de 100 epochs, predict() aplica o que aprendeu e recommend() usa as previsões para ordenar os produtos

O treinamento (Adam + ReLU + 100 epochs) é o professor.
A previsão (predict) é o aluno respondendo a prova.
A recomendação (recommend) é o resultado final que o usuário vê.
