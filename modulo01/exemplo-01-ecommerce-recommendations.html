Exemplo 01 — E-commerce Recommendations

Sistema de recomendação com TensorFlow.js que aprende no browser com o histórico de compras.

1 Visão Geral

O projeto implementa um sistema de recomendação de produtos para e-commerce que roda inteiramente no browser. Uma rede neural densa (TensorFlow.js) é treinada com o histórico de compras de usuários fictícios, aprendendo a prever se um usuário gostaria ou não de um produto. O código é organizado em 4 partes incrementais, cada uma adicionando uma camada de complexidade.

parte01

Estrutura base, dados, normalização, makeContext()

2 Conceitos Fundamentais

2.1 Dataset

O projeto usa dois arquivos JSON como fonte de dados:

  • users.json — lista de usuários com histórico de compras (purchaseHistory), idade, cidade e categoria favorita
  • products.json — catálogo de produtos com preço, categoria, cor, avaliação e número de vendas
É como a planilha de clientes de uma loja física. O modelo "estuda" essa planilha para aprender padrões — quem compra o quê e quais produtos têm características similares.

2.2 Normalização

Normalizar significa transformar todos os números para a escala [0, 1]. Isso garante que nenhuma feature "domine" o aprendizado por ter valores maiores.

src/workers/modelTrainingWorker.js — linha 9
const normalize = (value, min, max) => (value - min) / ((max - min) || 1)
Valor originalMinMaxNormalizado
150 (preço R$)105000.286
4.5 (avaliação)150.875
25 (idade)18600.167
Sem normalização, um preço de R$ 500 teria muito mais "peso" que uma avaliação de 4.5 só por ser um número maior — mesmo sendo igualmente importante para o modelo.

2.3 Feature Engineering

Feature engineering é a arte de transformar dados brutos em números que uma rede neural consegue processar. Cada produto é representado como um vetor de números:

src/workers/modelTrainingWorker.js — encodeProduct()
// produto vira um array de números:
// [preço_norm, avaliação_norm, vendas_norm, ...cores_onehot, ...categorias_onehot]
[0.286, 0.875, 0.42, 0, 1, 0, 0, 1, 0, 0, 0]
  • 2 features numéricas: preço normalizado, avaliação normalizada
  • Features categóricas: cor e categoria — cada uma vira um vetor One-Hot
  • Total: ~28 dimensões por produto
É como preencher uma ficha cadastral com campos específicos. A rede só entende números, então precisamos "traduzir" cada informação do produto para esse formato.

2.4 One-Hot Encoding

One-Hot Encoding converte categorias (texto) em vetores binários. Cada posição do vetor representa uma categoria possível — apenas uma posição é 1, o restante é 0.

src/workers/modelTrainingWorker.js — encodeProduct()
// Cria um mapa { categoria: índice } para cada valor único
const colorMap = Object.fromEntries(
  [...new Set(products.map(p => p.color))].map((c, i) => [c, i])
)
// Ex: { "preto": 0, "prata": 1, "branco": 2, "azul": 3 }

// Produto com cor "prata" → [0, 1, 0, 0]
const colorVec = Array(colors.length).fill(0)
colorVec[colorMap[product.color]] = 1

O resultado { "preto": 0, "prata": 1, "branco": 2, "azul": 3 } mapeia cada cor para uma posição no vetor. Um produto "prata" vira [0, 1, 0, 0] — o 1 na posição 1 sinaliza "sou prata".

2.5 Web Worker

Um Web Worker é uma thread separada no browser. O treino da rede neural é pesado e travaria a página se executado na thread principal — por isso é delegado ao Worker.

2.7 sessionStorage

O sessionStorage é usado para salvar o contexto de normalização (mínimos e máximos de cada feature) e os produtos codificados, evitando recalcular a cada nova recomendação durante a sessão.

src/workers/modelTrainingWorker.js — salvar contexto
// Salva na sessão para usar depois sem re-calcular
sessionStorage.setItem('normContext', JSON.stringify(context))
sessionStorage.setItem('encodedProducts', JSON.stringify(encodedProducts))

Os dados persistem apenas enquanto a aba do browser está aberta. Ao fechar, são apagados automaticamente — diferente do localStorage, que persiste entre sessões.

2.8 Sistema de Eventos

O projeto usa um sistema de eventos customizado (pub/sub) para desacoplar os componentes. Em vez de um módulo chamar outro diretamente, ele emite um evento — e quem estiver "ouvindo" reage.

src/events/events.js
export const events = {
  on(event, listener) {
    if (!this._listeners) this._listeners = {}
    if (!this._listeners[event]) this._listeners[event] = []
    this._listeners[event].push(listener)
  },
  emit(event, data) {
    if (!this._listeners?.[event]) return
    this._listeners[event].forEach(fn => fn(data))
  }
}

O padrão pub/sub (publicador/assinante) funciona assim: qualquer módulo pode publicar (emit) um evento, e qualquer outro pode assinar (on) para receber notificações.

É como um grupo de WhatsApp. Quem envia uma mensagem (emit) não precisa saber quem vai ler. Quem quer receber entra no grupo (on) e ouve quando chegar algo novo.

3 Fluxo Completo

Como as peças se encaixam do carregamento até a recomendação:

  1. 1 Página carrega → src/index.js inicializa todos os componentes (Controller, View, Services)
  2. 2 UserService.getDefaultUsers() e ProductService.getProducts() buscam os dados dos arquivos JSON
  3. 3 Controller cria o Worker e envia os dados via postMessage({ type: 'train', users, products })
  4. 4 Worker normaliza, codifica e treina a rede neural (100 epochs) — a UI permanece responsiva
  5. 5 Worker emite postMessage({ type: 'trainingComplete' }) → Controller habilita o botão "Recomendar"
  6. 6 Usuário clica em "Recomendar" → Controller chama recommend(userId) → model faz inferência → View renderiza os cards

4 Parte 02 — Encoding

A parte 02 introduz os pesos de features (WEIGHTS), One-Hot Encoding e a função encodeProduct().

FeaturePesoExplicação

sales1.0Popularidade é um sinal moderado
color1.2Preferência de cor é relevante

One-Hot Encoding na prática

Com 4 cores possíveis (preto, prata, branco, azul), um produto "prata" vira o vetor [0, 1, 0, 0]. Isso evita que a rede interprete cores como uma escala numérica (prata = 1, branco = 2...) quando na verdade são categorias independentes.

src/workers/modelTrainingWorker.js — encodeProduct()
function encodeProduct(product, context, products) {
  const { min, max, colors, categories } = context

  // Features numéricas normalizadas * peso
  const numericFeatures = [
    normalize(product.price, min.price, max.price) * WEIGHTS.price,
    normalize(product.rating, min.rating, max.rating) * WEIGHTS.rating,
    normalize(product.sales, min.sales, max.sales) * WEIGHTS.sales,
  ]

  // One-Hot para cor
  const colorVec = Array(colors.length).fill(0)
  colorVec[context.colorMap[product.color]] = 1

  // One-Hot para categoria
  const catVec = Array(categories.length).fill(0)
  catVec[context.categoryMap[product.category]] = 1

  return [...numericFeatures, ...colorVec, ...catVec]
}

Cada produto vira um array de ~28 números prontos para entrar na rede neural.

5 Parte 03 — Dados de Treino

A parte 03 adiciona encodeUser() e createTrainingData() — as funções que constroem os pares de entrada/rótulo usados no treino.

src/workers/modelTrainingWorker.js — encodeUser()
function encodeUser(user, context, products) {
  // Pega os produtos que o usuário comprou
  const purchasedProducts = products.filter(p =>
    user.purchaseHistory.includes(p.id)
  )

  // Calcula a média dos vetores dos produtos comprados
  const userVec = purchasedProducts.map(p => encodeProduct(p, context, products))
  return averageVectors(userVec)
}

O perfil do usuário é a média dos vetores de todos os produtos que ele comprou. Se Ana comprou fones (tech, prata) e tênis (esporte, preto), o vetor dela é a média entre esses dois — capturando suas preferências gerais.

src/workers/modelTrainingWorker.js — createTrainingData()
function createTrainingData(users, products, context) {
  const xs = []  // entradas: [vetorUsuário + vetorProduto]
  const ys = []  // rótulos: 1 = comprou, 0 = não comprou

  users.forEach(user => {
    const userVec = encodeUser(user, context, products)
    products.forEach(product => {
      const productVec = encodeProduct(product, context, products)
      xs.push([...userVec, ...productVec])  // concatena os vetores
      ys.push(user.purchaseHistory.includes(product.id) ? 1 : 0)
    })
  })

  return { xs, ys }
}

Para cada par usuário-produto é gerado um exemplo de treino:

Entrada (xs)Rótulo (ys)
vetor(Ana) + vetor(Fones Bluetooth)1 — Ana comprou fones
vetor(Ana) + vetor(Boné Estiloso)0 — Ana não comprou boné
vetor(Bruno) + vetor(Fones Bluetooth)1 — Bruno comprou fones
